# Founding directive

Idol WSP was founded by Chris's direct order on 2026-11-07 at 17:38 PST,
with two amendments in the following minute. His words are the founding
record and are quoted here as his.

## The directive (2026-11-07 17:38 PST)

> Create a new repo called Idol WSP, standing for Idol Weight Space
> Programming. It serves only to be an instantiation of Idol's weight
> space — on-the-fly rewriting / reweighting experiments. The end
> deliverable is an as-compact-as-possible proof of concept for a live
> rewriting coding agent: highly sophisticated tool use, integrated with
> Idol Eyes, all MCPs, everything — a highly sophisticated tool-using AI
> model that is extraordinarily compact.

## Amendment 1 — performance, learning, substrate (2026-11-07 17:38–17:39 PST)

> It should by far outperform any similar size models by like an
> incomprehensible margin. And it should furthermore be as fast as
> possible and learning. It should learn on the repos that it works in.
> And do so through live rewriting facilitated through Idol model and
> Idiom and Idol based semantic graph and rewriting and reweighting and
> state machine capabilities.

What this binds, in the program's own terms:

- The bar is beat-by-far at equal size. It is stated in
  [status.md](status.md) as a comparison cell with same-contract terms
  (same tasks, same tool surface, size = parameter count + bits per
  weight) and stands UNMEASURED until a same-contract run exists. No
  margin is ever claimed without that run.
- Speed is a deliverable: each slice lands with measurements at a named
  pin, and its representation is identity-keyed from the first commit —
  no text-rescan mechanism (the state-machines kernel's measured defect
  class is this program's standing warning).
- Learning on the repos it works in is a core mechanism, not a later
  phase: working in a repo changes the agent's weight space, and what it
  learned persists as weight-space state tied to that repo. The loop runs
  through the named substrate — idol-model and Idiom as the model and
  decision faces; Idol's semantic graph, rewriting and reweighting, and
  state machine capabilities as the mechanism. A repo's facts enter as
  premises in the semantic graph; learning is a premise-tracked rewrite
  or reweighting, so what was learned from a withdrawn or corrected
  premise retracts exactly its cone. The state-machine machinery's
  withdrawal law is the learning loop's safety property.

## Amendment 2 — pure Idol, triple proof (2026-11-07 17:39 PST)

> It should be in pure Idol as a proof of concept both language and for
> the model and for the weight space programming.

What this binds:

- Everything in this repo is pure Idol: the agent, the model, the
  weight-space instantiation, the tool-use loop. No foreign language,
  runtime, or intermediary anywhere in any slice. Any unavoidable host
  seam is named in [status.md](status.md) as a defect with its
  elimination path, in the same commit that introduces it — never
  silently absorbed.
- The deliverable proves three things at once — the language, the model,
  and weight space programming itself — and [status.md](status.md)
  tracks the three separately, because they can move at different
  speeds and one must never be reported as another.

## The repo-truth law (2026-11-07 17:34 PST, minutes before the directive)

Chris's order, as spoken: the repo "shouldn't be empty. You should create
and populate it" — a project's repo "should always be a live source of
truth as to what exists canonically." An empty repo for a named project
is a defect. This repo was created at 17:38 PST and populated in its
first commit the same day; its status document is updated in the same
commit as any landing thereafter.
